## 8 模块骨架(按 depth 取舍)

### 1. 基本判断

回答一句话:`这个行业/公司做什么?核心赚钱方式是什么?`

```markdown
一句话定位:XX 平台的核心是「收租 + 广告」,向商家收交易佣金,
向品牌收广告费,利润厚度取决于它对流量的分配权。
```

### 2. 业务逻辑

链路:`客户是谁 → 提供什么价值 → 如何交易 → 如何履约 → 如何收费`

```markdown
消费者(找便宜货、图方便)→ 平台提供「聚合供给 + 履约」价值 →
线上下单 → 配送/到店履约 → 平台按交易额抽佣 + 收广告费
```

### 3. 收入与成本

分两小块:收入从哪来(带大致占比);成本里哪些随业务量变、哪些固定。

```markdown
收入:佣金 ~40% + 广告 ~30% + 其他 ~30%
成本:采购成本(变动)、配送履约(半变动)、研发(固定)
```

### 4. 利润池(重点模块,depth 标准以上必深入)

四问:利润沉淀在哪些环节 / 哪些厚哪些薄 / 为什么厚 / 被什么侵蚀。

```markdown
排序:广告位(毛利率 70~85%,厚)> 佣金(中)> 履约(薄)
广告位厚的原因:流量垄断 → 定价权(六点归因:定价权/成本优势/
竞争壁垒/规模效应/网络效应/资源稀缺)
侵蚀因素:监管压 Take Rate、竞争分流
```

### 5. 关键经营指标(三层,不凑数量)

按 `流量层 → 交易层 → 盈利层` 组织;每个重点指标写:含义/计算/驱动/影响。

```markdown
流量层:DAU、新客数
交易层:GMV、客单价、Take Rate、频次
盈利层:毛利率、净利率、UE、DSO
指标卡格式:含义 → 公式 → 驱动 → 对财务的影响
只有存在可靠行业基准时才给区间/标杆。
```

### 6. 财务三表(传导链写法)

核心:`什么业务变化 → 影响什么科目 → 为什么`,用一笔业务走通三表。

```markdown
一笔 100 元订单:
利润表:确认收入 100(净额法只记佣金 5)
资产负债表:应收账款 +5(未结算)、合同负债 +100(预收)
现金流量表:经营性现金流入 100
```

### 7. 公司/模式对比(没有可靠信息就不硬比)

比四件事:收入模式 / 成本结构 / 利润来源 / 核心经营指标。

```markdown
| 公司 | 收入模式 | 毛利率 | 核心指标 |
| A | 自营差价 | 28% | 存货周转 |
| B | 平台佣金 | 80% | Take Rate |
无可靠数据时直接省略本模块,不注水。
```

### 8. 财务 BP 洞察(只留最重要的)

`利润杠杆 + 关键风险 + 应重点跟踪的经营变量`,纯干货,不写追问。

```markdown
杠杆:拉升 Take Rate、压低履约成本
风险:政策监管、补贴军备竞赛
跟踪变量:单均 UE、广告加载率
```

## 模块取舍速查(§3.4)

| depth | 模块策略 |
| ----- | -------- |
| 概览 | 保 1、2、4、8,其余一段带过 |
| 标准 | 覆盖主要模块,按 focus 增减笔墨 |
| 深度 | 重点展开 4、5、6,利润池验持续性、三表走传导链 |
| 用户指定 focus | 相关模块加重,其余精简 |
| 面试场景 | 穿插「面试要点」+ 末尾加「面试一句话备用」+ 优先展开岗位相关模块,其余精简;不写追问 |

## 反面清单(写报告时对照)

- ❌ 背景资料堆砌(公司简介照搬百科)
- ❌ 为凑指标数量写低价值指标
- ❌ 数据不标可信度来源
- ❌ 结论用「预测」代替「分析」
- ❌ 正文写用户追问、开放式提问
