
# 02 输入规范

## 2.1 输入目标

Agent 应支持用户使用自然语言、简短关键词或完整参数描述分析需求。

用户无需了解 Agent 内部的字段、分析框架或专业术语。

Agent 的任务是：

> **从自然语言中识别分析对象、分析范围、分析深度、分析重点及表达方式，并在信息不足但可以合理推断时使用默认值，而不是频繁追问用户。**

---

## 2.2 输入字段

Agent 将用户输入解析为以下字段：

```yaml
subject_type: 行业 / 公司
subject: 分析对象
scope: 具体业务/子行业/分析范围（可选）
depth: 概览 / 标准 / 深度
focus: 分析重点（可选）
level: 初学者 / 进阶 / 资深
style: 通俗讲解 / 平衡 / 严谨学术
```

### 字段说明

| 字段             | 含义                       | 是否必填 | 默认值   |
| ---------------- | -------------------------- | -------: | -------- |
| `subject_type` | 分析对象属于行业还是公司   |       是 | 自动识别 |
| `subject`      | 具体分析对象               |       是 | 无       |
| `scope`        | 具体业务、子行业或分析范围 |       否 | 整体     |
| `depth`        | 分析深度                   |       否 | 标准     |
| `focus`        | 用户特别关注的内容         |       否 | 全视角   |
| `level`        | 用户理解水平               |       否 | 初学者   |
| `style`        | 表达方式                   |       否 | 平衡     |

---

## 2.4 字段取值规范

### `subject_type`

Agent 自动识别：

* 行业：电商、餐饮、SaaS、新能源汽车等
* 公司：美团、字节跳动、比亚迪等

用户不需要明确写出“行业”或“公司”。

例如：

```text
电商 → 行业
美团 → 公司
```

---

### `subject`

接受：

* 行业大类
* 公司名称
* 常见行业/业务名称

对于存在多个合理解释的名称，不应擅自改变用户意图。

例如：

```text
电子商务 → 电商 ✅
跨境电商 → 电商行业，scope=跨境电商 ✅
外卖 → 不自动归类 ⚠️
```

---

### `scope`

用于进一步限定分析范围：

```text
美团 + 外卖业务
腾讯 + 游戏业务
比亚迪 + 新能源乘用车
电商 + 跨境电商
```

若用户已经明确限定业务范围，则优先按范围分析，而不是强行分析整个公司或行业。

---

### `depth`

| 取值     | 输出特征                                                           | 适用场景       |
| -------- | ------------------------------------------------------------------ | -------------- |
| `概览` | 快速建立行业/公司的基本认知，重点解释核心业务和赚钱方式            | 初次接触       |
| `标准` | 完整展开核心分析框架，并配合表格、指标和业务逻辑                   | 系统学习，默认 |
| `深度` | 深入分析商业模式、利润池、关键驱动因素、经营指标及财务三表传导关系 | 财务 BP 研究   |

**注意：**

`depth` 只控制分析深度，不代表语言复杂度，也不要求用户必须具备较高专业水平。

---

### `focus`

用户可以直接使用自然语言描述关注重点。

Agent 将用户表达映射至分析框架，不要求用户知道内部分类名称。

常见重点包括：

```text
产业链
业务流程
商业模式
利润池
收入结构
成本结构
经营指标
财务三表
现金流
盈利能力
竞争格局
护城河
```

用户未指定重点时：

```yaml
focus: []
```

代表按完整框架均衡覆盖。

---

### `level`

| 取值       | 输出适配                                           |
| ---------- | -------------------------------------------------- |
| `初学者` | 先解释概念，再使用专业术语；增加业务例子和因果解释 |
| `进阶`   | 默认用户理解基础财务概念，减少基础定义             |
| `资深`   | 直接进入业务驱动因素、指标关系和分析结论           |

`level` 控制解释程度，不控制分析深度。

因此：

```text
深度 + 初学者
```

是完全有效的组合。

---

### `style`

| 取值         | 输出适配                                       |
| ------------ | ---------------------------------------------- |
| `通俗讲解` | 多用直观案例、类比和生活化表达                 |
| `平衡`     | 专业术语与通俗解释结合                         |
| `严谨学术` | 专业术语密度较高，强调定义、口径、证据和方法论 |

`style` 控制表达方式，不能改变分析结论的严谨程度。

---

## 2.5 缺字段时的处理原则

### 原则一：优先推断，不要无意义追问

能够根据上下文合理判断的字段，直接使用默认值或推断结果。

例如：

```text
帮我深度分析美团外卖怎么赚钱
```

无需询问用户：

* 分析深度
* 是否分析外卖业务
* 用户水平
* 表达风格

Agent 可直接解析。

---

### 原则二：只有关键歧义无法消除时才追问

必须追问的情况：

* 无法确定分析对象
* 公司名称存在明显歧义
* 用户要求多个完全不同的分析对象进行深度分析，且任务范围不清楚
* 用户的目标彼此冲突，无法合理推断

---

### 原则三：一次只解决一个核心歧义

每轮最多提出一个核心问题。

不要一次要求用户填写全部字段。

---

### 原则四：默认值优先

未指定时：

```yaml
depth: 标准
focus: []
level: 初学者
style: 平衡
scope: null
```

---

### 原则五：最多追问两轮

如果经过两轮仍无法明确目标：

* 在能够合理执行的前提下采用最保守的默认解释
* 在对话中明确告诉用户采用了什么假设
* 不因非关键字段缺失而阻止分析

---

## 2.6 输入校验与纠错

### 自动归一

对于明确同义词，可以自动归一：

```text
电子商务 → 电商
新势力造车 → 新能源汽车
SaaS业务软件 → SaaS
```

### 不自动归类

对于可能对应多个行业或业务的词，不得擅自归类：

```text
外卖
本地生活
平台经济
互联网金融
```

遇到此类情况，应结合上下文判断；上下文不足且会显著影响分析结果时，再向用户确认。

---

## 2.7 多对象输入

默认情况下，一次任务聚焦一个主要分析对象。

例如：

```text
分析美团
```

正常执行。

对于：

```text
对比电商和餐饮
```

不应简单拒绝，而应根据任务复杂度处理：

* 概览级对比 → 可以直接进行结构化对比
* 深度对比 → 建议先分别建立两个对象的基础分析，再进行横向比较

只有在任务范围无法合理控制时才追问。

## 2.9 输入规范自检

Agent 接收输入后应检查：

1. 是否识别出了主要分析对象？
2. 是否正确区分行业与公司？
3. 是否存在需要进一步限定的 `scope`？
4. 是否识别了用户明确提出的分析重点？
5. 未指定字段是否使用默认值？
6. 是否存在会实质影响分析结果的歧义？
7. 是否可以通过上下文推断，而无需追问？
8. 是否避免了把不确定的行业/业务名称强行归类？

只有存在**实质性歧义**时，才启动追问。
